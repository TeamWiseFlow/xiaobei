# 平台运行库分发

四平台工具使用固定的 `xiaobei-platform-backend` 分发包。`runtime-profile.json` 记录包版本、SHA-512、平台注册表校验值、依赖和发布资源地址。运行库的业务模块不由客户端安装器修改。

## 安装与预下载

项目统一依赖安装器调用 `platform-runtime/scripts/install-runtime.mjs`，不要在技能执行期间临时安装依赖。

安装器按下列顺序查找完整分发包：

1. `XIAOBEI_PLATFORM_RUNTIME_ARCHIVE` 指定的文件。
2. `XIAOBEI_CACHE_DIR` 下的固定文件名；未设置时为 `~/.xiaobei/cache/xiaobei-platform-backend-0.1.0.tgz`。
3. 技能私有安装缓存中的同名文件。
4. 配置锁定的小贝发布资源。

命中本地文件后先校验完整性，校验不符立即停止，不绕过错误继续下载其他文件。预下载包保留原文件名即可，不需要修改业务技能的配置。

解包后继续核对四平台范围、依赖清单、注册表和适配协议。依赖安装与原生模块检查在临时目录完成；全部通过后才替换运行库和标记，替换失败恢复旧目录。既有会话、浏览器身份、发布收据和业务数据库不随依赖替换迁移或清理。

## 发布资源准备

客户端发布前，维护者必须把与配置 SHA-512 一致的包放到锁定发布资源中，或随安装包预置到上述缓存。尚未上传资源时，使用已准备的本地包完成构建和安装验收，不宣称在线获取已通过。

包内 `runtime-contract.json` 定义状态目录环境变量、错误类型导出和原始响应符号。适配代码读取该协议，不在公开配置中绑定底层实现名称。旧版固定运行库在完整替换前可通过已验证的注册表、版本和依赖识别，并读取其既有适配接口；业务和签名模块保持原样。
