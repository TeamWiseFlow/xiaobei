# 起号、定位梳理与老号接手 Workflow

新号起号、账号定位梳理、内容支柱搭建、默认 `dna-0` 初始化、老号接手与诊断走这个 Workflow。独立账号对标走 `account-benchmark.md`。

起号拆成六件事：定位清楚、点击理由成立、标签稳定、内容有用、互动真实、复盘持续。方法库里的技巧和案例都是启发，不要把具体数字当成保证；平台机制数字、趋势判断和经验阈值只能当作经验启发，不要当成官方规则或永久有效结论。产出要能直接执行：表格、清单、笔记简报、30 天节奏或复盘动作，少写空泛建议，多给"下一篇笔记该怎么做"。

## 入口判断

用户说以下话时走：

| 意图 | 典型说法 | 处理 |
| --- | --- | --- |
| 新号起号 | "我想做个小红书号，从零开始" | 业务信息检查 -> 信息收集 -> 定位梳理 -> 初始 `dna-0` |
| 定位梳理 | "梳理一下内容方向""搭建内容支柱" | 定位梳理 -> 必要时更新 `dna-0` |
| 老号接手 | "这个号以后你来接手""账号还行，先按原风格做" | 老号样本采集 -> 建立或更新 `dna-0` |
| 老号诊断 | "帮我看看这个号还有没有救""给我们号把个脉" | 老号样本采集 + 诊断速查 -> 判断延续或重建 |
| 默认 DNA 初始化 | "初始化默认 DNA" | 按新号 / 老号路径建立 `dna-0` |

## 从零开始打造新号

### 初始化原则

1. 默认 DNA 固定为 `dna-0`。
2. 除 `account-benchmark.md` 分流的对标样本外，用户不指定 DNA 时，参考笔记和后续新增样本默认累积到 `dna-0`。
3. `dna-0` 可以由参考账号、参考笔记、用户想法和 `business_knowledge.md` 共同形成，不绑定单一账号名。
4. 若 `xhs/dna/dna-0/dna-0.dna.md` 已存在，不覆盖重建；新资料按 `style-dna.md` 的更新流程进入。
5. 独立对标样本不直接写入 `dna-0`，必须走 `account-benchmark.md` 并进入独立 DNA；用户明确采纳的局部规则可通过局部 DNA 融合更新 `dna-0`。

### Step 1 - 业务信息检查

先读取 Workspace 根目录的 `business_knowledge.md`，检查三项关键信息：

| 关键信息 | 最低要求 |
| --- | --- |
| 产品 / 服务概括 | 能说明卖什么、解决什么问题、核心差异 |
| 收费项目 | 能说明主要收费方式、产品或价格区间 |
| 目标受众 | 能说明具体人群、痛点、使用场景 |

任一项为空、仅有占位符或互相矛盾时，先与用户补齐。不要凭空编造。

用户思路不清晰、多个定位方向难以取舍或商业假设冲突时，调用顶层 `council` 技能辅助梳理；`council` 不收纳进小红书专家包。

更新 `business_knowledge.md` 前必须征得用户同意，并遵守 Workspace 根 `AGENTS.md` 的治理规则。

### Step 2 - 起号信息收集

向用户收集（已知项跳过，推断项标注推断依据）：

| 字段 | 需要询问或推断的内容 |
| --- | --- |
| 赛道 | 账号属于什么品类、产品或服务？ |
| 可交付物 | 用户能卖什么、收集什么线索、验证什么需求？ |
| 受众 | 谁痛点最强、购买能力最强、最需要被理解？ |
| 证据 | 有哪些案例、结果、照片、截图、资质、故事或作品？ |
| 约束 | 是否涉及敏感声明、监管行业、品牌边界或隐私风险？ |
| 产能 | 每周能稳定产出多少篇，不牺牲质量？ |
| 阶段 | 新号、停更号、活跃号、低流量号、违规风险号还是放大期？ |

做日历之前先判断三件事，避免两类常见错误：追一个自己无法持续的风口，或在没有发布反馈前过度打磨定位。

| 维度 | 核心问题 | 应产出的内容 |
| --- | --- | --- |
| 风口 | 当前是否有内容浪潮、季节需求、平台行为或社会语境正在放大？ | 3-5 个机会角度，并标注是否需要实时核验趋势 |
| 定位 | 用户有什么兴趣、能力、证据和不可复制优势，能长期输出？ | 定位句、内容支柱和"不做清单" |
| 共鸣 | 什么会让受众感觉被帮助、被看见、被理解、被鼓励？ | 情绪钩子库、受众原话、评论引导问题 |

如果来源材料说某个趋势正在火，把它当成时间敏感信息：用户要当前起号建议时，用 `xhs-hunter search-notes '趋势关键词' --count 20 --sort 1` 查看一页近期站内样本，再做判断；没有可核验样本时不要称其为当前热点。

账号打法也要先明确，不要默认所有账号都追同一种增长：

| 打法 | 适合谁 | 节奏 |
| --- | --- | --- |
| 流量冲刺 | 喜欢追趋势、做产品验证、研究爆款形式的人 | 高频发布，快速复盘 |
| 个人 IP 长跑 | 专家、创业者、教练、有真实经历和长期品牌目标的人 | 稳定周更，长期沉淀 |
| 混合打法 | 本身能力刚好踩中风口的人 | 风口笔记 + 固定信任系列 |

判断原则：不要只优化粉丝数。一个信任度、购买意图和反复关注都更强的小众受众，可能比大量路人粉更有价值。

### Step 3 - 定位梳理

新号起号、老号重建和用户要求"梳理定位 / 内容支柱"时都必须执行。已有清晰定位且用户只要求接手制作时，可以基于现有账号样本校验定位，不重新发起完整讨论。

#### 输出（起号计划字段）

1. **定位句**：`我帮助 [目标客户] 用 [方法/产品/证据] 解决 [具体问题]，从而获得 [理想结果]。`
2. **点击理由**：陌生人在发现页刷到时为什么要停下来点进来；看完能记住账号的哪个身份、冲突、热情或承诺。每篇笔记都要能回答这两个问题，回答不了的选题不做。
3. **不可复制优势**：从人生经历、专业证明、审美或生活方式、学习边缘（比新手领先一步，公开记录学习过程）、资源通道中找出用户独有的一项，作为内容记忆点。
4. **内容支柱**：3-5 个可重复栏目，分别服务搜索、信任、证明、互动和转化。
5. **关键词宇宙**（标签反推 + 搜索预埋，方法见 `account-benchmark.md` 的关键词提取规则）：
   - 选 5-10 个对标账号，优先低粉爆款（粉丝少但互动高，内容形式可学习）；按 `account-benchmark.md` 流程搜索、下载、分析，记录主标签、细分人群、核心场景、常见痛点、标题高频词、评论高频问题。
   - 汇总成 `1 个主关键词 + 2-4 个场景词 + 3-5 个人群痛点词`，并按层级展开：核心词（赛道本体）、长尾痛点词（用户真实搜索句）、场景词（时间/人群/预算/身份）、转化词（清单/步骤/避坑/对比/测评/教程）。
   - 这些词写进昵称、简介、前 10 篇标题、正文开头、话题标签和置顶笔记。
6. **主页文案**：昵称（包含一个好记的人物身份或品类关键词）、简介（说清价值、证据和更新承诺，不放违规联系方式或诱导表达）、置顶笔记规划、视觉方向。
7. **选题库雏形**：按笔记任务分类，每个支柱至少 5 个候选选题，前 30 天选题按起号日历排布：

   | 任务 | 目的 | 示例模式 |
   | --- | --- | --- |
   | 搜索 | 承接主动需求 | "[产品/问题]怎么选""[品类]避坑""[场景]攻略" |
   | 信任 | 证明专业度 | 案例拆解、过程公开、错误复盘 |
   | 互动 | 收集评论并训练受众信号 | 提问、投票、经验分享 |
   | 证明 | 降低购买犹豫 | 前后对比、客户故事、对照表、清单 |
   | 转化 | 把合格用户推向下一步 | 服务说明、FAQ、真实但不过度的名额/安排 |
   | 留存 | 让用户记住账号 | 系列、个人观察、幕后记录 |

8. **约束与风险**：合规边界、宣传限制、版权、品牌语气、产能。

用户思路不清、多个方向冲突或商业假设不一致时，先用少量问题澄清；仍难判断时调用顶层 `council` 技能辅助决策。

普通内容改造参考（把平铺内容变成有点击理由的版本）：

| 平铺内容 | 可看版本 |
| --- | --- |
| 展示产品很好 | 发起一个有趣的复刻、挑战、测评或对比系列 |
| 讲自己很专业 | 公开解决一个真实难题，并展示判断过程 |
| 直接教知识点 | 带着具体场景、限制条件或失败案例去解决 |
| 展示日常工作 | 把工作过程包装成任务、闯关、实验或复盘 |

### Step 4 - 起号准备清单

把清单当作质量门槛，不要承诺"完成这些就一定被推荐"：

| 模块 | 检查点 |
| --- | --- |
| 主页 | 头像清楚，昵称带识别点，简介表达价值，视觉方向一致 |
| 内容方向 | 一个主赛道，起号期避免频繁跨类目漂移 |
| 素材 | 至少 20 条原始素材：图片、案例、问题、异议、过程截图、可合规展示的前后对比 |
| 合规 | 不隐藏联系方式，不夸张承诺，不做禁限品类，不虚假稀缺，不误导证明 |
| 搜索 | 标题、正文、标签和选题自然包含核心关键词 |

新号或停更号正式发布前的准备节奏：

- 浏览、收藏目标赛道内容，让推荐流逐渐贴近目标领域；自然关注和收藏对标账号。
- 定位明确后再完善主页。
- 发布前准备 10-15 篇候选笔记。
- 以可持续节奏发布；每天 1-3 篇只适合产能和质量都跟得上的情况。
- 避免刷量、互赞互粉、垃圾评论和任何操纵推荐系统的行为。

垂直度分阶段推进：早期内容垂直（足够窄，让平台和用户知道账号讲什么）-> 中期人设垂直（相邻话题可以成立，但必须延展同一个人、价值观和受众承诺）-> 成熟期信任垂直（主题可谨慎扩展）。用户兴趣很多时，建议先做一个主账号；不建议批量矩阵、滥用账号或人为制造增长。

### Step 5 - 新号初始 DNA 路径判断

先区分两种"参考"：

- 用户明确要把参考账号或笔记作为默认 DNA 的初始来源 -> 走下方路径 A / B / C，产物进入 `dna-0`。
- 用户只是要分析参考账号、比较风格差异或寻找可借鉴模式 -> 走 `account-benchmark.md`，对标样本进入独立 DNA，不直接写入 `dna-0`。
- 意图不明确时，先向用户确认"是纳入默认 DNA，还是只做对标比较"。

#### 路径 A：用户提供了参考账号或参考笔记

1. 按 `style-dna.md` 获取样本：
   - 图文笔记链接：`xhs-hunter fetch` 下载正文、图片与互动数据，整理为样本文件
   - 视频笔记链接：self-spawn subagent 走 `viral-chaser` 拆解
   - 本地文字稿 / 笔记草稿：直接整理为样本 `.md` 输入 profiler
2. 目标 DNA 固定为 `dna-0`。
3. 每篇生成 report。
4. 运行 `xhs-style-profiler build --dna-id dna-0`，生成 DNA 文档与 template。
5. 把定位、选题、标题包装、账号简介、图文/视频比例、发布习惯、高数据创意、搜索关键词与用户问题、口播 DNA 与制作管线发送用户确认。
6. 用户调整意见按 `style-dna.md` 的"用户输入转译"更新到 `dna-0`。

用户没有明确权重时，所有 report 默认权重为 1。

#### 路径 B：用户暂无参考，但业务信息完整

Agent 基于 `business_knowledge.md` 和关键词宇宙提炼搜索关键词，按 `account-benchmark.md` 的搜索流程（含低粉爆款筛选）在小红书找头部或表现较好的笔记，下载后经用户确认纳入 `dna-0`。

给用户的搜索建议必须说明：

1. 优先找受众相近、承诺清晰、近期仍活跃的账号；优先低粉爆款账号（粉丝与自己体量近似但互动明显更高，内容形式可学习）。
2. 优先选择点赞、收藏、评论信号强的笔记；单一互动数只作参考之一。
3. 对标账号初始参考建议批量收集 10 篇笔记（图文进 `dna-0`，视频进 `dna-0-video`）；用户明确提供单篇或少量样本时仍可建立 DNA，但必须标注覆盖不足，不得称为稳定结论。批量账号样本才填账号运营子模块（简介写法、内容形式比例、发布习惯）。

用户补回账号名或笔记链接后，回到路径 A。

#### 路径 C：用户拒绝外部参考或已有明确想法

1. 结合 `business_knowledge.md`、用户定位、目标读者、变现方式和用户思路，提炼 `dna-0`。
2. Agent 直接按维度框架编写（图文用 `note-dna-framework.md`，视频用 `video-dna-framework.md`）：

```text
xhs/dna/dna-0/dna-0.dna.md
xhs/dna/dna-0/dna-0.template.md
```

3. DNA 文档必须标明来源是"业务信息 + 用户指定方向"，没有笔记样本统计。
4. 能确定的规则写为执行要求；未确定维度写"待校准"，不得虚构单篇证据。
5. Template 仍必须给出可执行语义段：图文 = 图文写作模板（含关键词与用户问题）；视频 = Brief 正文 + 口播文案模板。不能只有抽象定位词。
6. 将 DNA 摘要和待校准点发给用户确认，再按用户意见转译修订。

后续获得真实笔记样本时，按 `style-dna.md` 生成 report 并更新 `dna-0`。

### Step 6 - 默认 DNA 落盘

完成路径 A / B / C 后，确认以下文件存在且互相一致：

```text
xhs/dna/dna-0/reports/
xhs/dna/dna-0/covers/
xhs/dna/dna-0/dna-0.dna.md
xhs/dna/dna-0/dna-0.template.md
```

检查要求：

- DNA 文档说明样本来源、覆盖数量、权重、例外和待校准点。
- Template 能由 DNA 文档推导，直接指导定位、选题、标题包装、内容形式、发布节奏、高数据创意、搜索意图、互动与制作交接。
- 用户输入已转译为维度级规则，不是原话堆积。
- 对标样本 report 不混入 `dna-0`；用户采纳后，只有转译后的规则通过局部 DNA 融合进入 `dna-0`。

## 老号接手

### Step 1 - 获取老号样本

1. 请用户提供老号最近的代表性笔记链接（原则上至少 10 篇，账号作品不足 10 篇时提供全部并说明）。
2. 图文笔记用 `xhs-hunter fetch` 逐篇下载（间隔 5-10 秒），视频笔记走 `viral-chaser`；剔除重复、删除和无效样本；保留标题、正文、发布时间、账号简介、内容形式、关键词/用户问题、图组、互动数据和作者信息。
3. 用户也可补充创作者中心后台截图（阅读、粉丝画像），作为诊断线索，不编造。

### Step 2A - 账号基本可用，用户让 Agent 接手

用户对账号目前的情况基本满意，目的是让 Agent 接手，延续目前账号的风格。

1. 将老号笔记生成属于 `dna-0` 的 DNA report。
2. 若 `dna-0` 不存在：运行 `xhs-style-profiler build --dna-id dna-0`，建立默认 DNA 文档与 template。
3. 若 `dna-0` 已存在：新增 report 后按 `style-dna.md` 更新 `dna-0`，不覆盖重建。
4. 将 DNA 摘要、可复用规则和待校准点发给用户确认。
5. 用户意见按"用户输入转译"更新 `dna-0`，后续内容生产默认使用 `dna-0`。

### Step 2B - 用户认为账号不太可用，需要推倒重来

1. 基于 Step 1 拿到的样本提炼定位、账号简介、选题组合、标题包装、图文/视频比例、发布节奏、搜索关键词与用户问题、核心卖点与 CTA 等基础信息，将这些信息与用户确认。
2. 结合上述信息，走「从零开始打造新号」流程。
3. 如果 `business_knowledge.md` 不全，可以先从 Step 1 的样本中提取，不足的信息与用户讨论。

### 老号诊断速查

有样本时先自行分析（定位、内容支柱、标题包装、搜索意图、图文/视频比例、互动设计、发布节奏），再向用户补问缺失信息。按笔记失败环节倒推：

| 现象 | 可能问题 | 修正方向 |
| --- | --- | --- |
| 曝光低 | 账号/品类信号不清，可能有合规问题，赛道一致性弱 | 收紧定位，检查风险，发布更多垂直内容 |
| 有曝光但阅读低 | 封面/标题弱，承诺不清，视觉证明不足 | 提升封面对比、标题具体度和关键词意图 |
| 有阅读但收藏低 | 不够有用，缺少清单/流程，观点多工具少 | 增加步骤、判断标准、模板、对比 |
| 有阅读但评论低 | 没有问题、冲突或身份触发 | 增加具体评论问题或决策矛盾 |
| 有互动但不涨粉 | 单篇有用，但账号承诺不清 | 强化主页和系列承诺 |
| 有关注但无咨询 | 行动引导弱或服务不清 | 让下一步更平台内、更清晰、更价值优先 |

不同品类基准差异很大，优先用用户所在赛道的基线，不要迷信通用阈值。基础数据之外再做共鸣判断：

| 信号 | 解读 |
| --- | --- |
| 评论说"这就是我" | 情绪共鸣强，可以扩展成系列或框架 |
| 收藏多但关注少 | 单篇有用，账号承诺不够清晰 |
| 关注有增长但评论弱 | 信任可能在形成，但互动问题太封闭 |
| 多篇都弱 | 重新检查风口、承诺、证据，以及创作者是否隐藏了最有辨识度的部分 |

阈值只作为经验提示，不能机械判断。样本太小时，先收集 10-20 篇同类内容再做大调整。诊断结论指向系统性风格问题时，引导走 `review.md` 做 DNA 评估。

## 人设、信任与活人感（写作时参照）

小红书常常更像"杂志 + 真人秀"：用户不只看信息，还会判断内容背后这个人的生活、审美、故事和可信度。不要包装完美人设，要用具体真实建立信任：

| 层级 | 表达方式 |
| --- | --- |
| 活人感 | 露脸、声音、手写、工作台、日常场景、适度承认真实不确定 |
| 证明 | 案例、工作过程、合规前后对比、截图、样例、作品集 |
| 有用 | 清单、模板、判断标准、避坑、对比 |
| 共鸣 | "这个问题我懂""这种感受我也经历过"的瞬间 |
| 一致性 | 固定栏目、稳定价值观、重复语言、可识别视觉节奏 |

露脸和视频通常有助于建立信任，但不要强迫用户露脸。提供隐私友好替代方案：手部演示、桌面场景、语音旁白、过程图、标注截图或固定视觉符号。

## 流量模型（归因心智模型）

把流量解释成三个入口：

- **推荐流量**：受选题匹配、点击率、互动、关注意愿和账号一致性影响。
- **搜索流量**：受关键词需求、笔记相关性、账号权重和长期内容质量影响。
- **分享流量**：受实用性、情绪、稀缺感、身份认同和转发价值影响。

## 起号底线（合规）

- 合规转化替代方案：让用户在平台内评论清楚的问题并在平台内回答；只在规则允许时使用官方群聊、话题、店铺、企业号能力或平台批准的线索工具；用连续内容、置顶 FAQ 和可见证明建立信任，不强行跳转私域。
- 私域冷启动只请真实相关人群给反馈或补充问题，不要求统一互动。
- 不以利益换互动（"点赞关注才给资料"是高风险做法）；评论引导走价值承接。
