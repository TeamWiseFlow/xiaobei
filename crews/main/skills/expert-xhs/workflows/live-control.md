# 直播控场 Workflow

适用：用户要求监看、协助主持或回应指定的小红书直播间。直播控场只处理文字互动与事件分析，不执行赠礼、充值或其他支付操作。

当前接口提供观众侧事件与文字互动，没有禁言、踢人、改价、上架商品等主播后台控制能力；需要这些操作时交主持人或平台后台处理。

## 1. 明确范围

取得直播间 `room_id`、主播 `host_id`、用户希望处理的事件类型、允许发送的文案或答复原则、值守时长与升级联系人。区分自有直播间和他人直播间；没有发送权限时仅监听并给出建议。发评论或私信前，向用户展示目标与确切文案并取得授权。

## 2. 连接与观察

先检查 `xhs-hunter check`。没有 PC 登录态时走 `xhs-hunter login` 并把二维码图片交用户扫码。用 `xhs-live call current_room_info --args '["<room_id>"]'` 验证房间状态，再按短时窗口监听：

```bash
xhs-live listen --room-id '<room_id>' --seconds 60 --max-events 100
```

记录实际收到的弹幕、提问、进场、点赞、关注与礼物事件，按时间线整理。原始帧未解码时只标记“未知事件”；不能臆测观众身份或行为。每个窗口结束后根据已收到事件决定下一轮是否继续，避免无限后台监听。

## 3. 控场决策

- 提问：从用户给定的产品事实、价格、活动规则或现有知识库核对答案；无依据时记待答，不即时编造。
- 负面反馈与投诉：摘出原话、上下文和时间，优先提示主持人；涉及订单或个人信息时转私密渠道，不在公开弹幕披露。
- 重复问题：汇总成 FAQ，建议主持人集中回应，避免机器人式刷屏。
- 高意向线索：只记录公开且必要的信息，后续是否私信由用户决定。

需要发送直播评论时运行 `xhs-live send <room_id> '<批准文案>' --host-id <host_id>`。返回成功仅说明接口接受本次提交；结果不明时先到直播间核对，不自动重发。私信单独按 `xhs-im` 的会话查询、用户确认和发送步骤执行，不能把直播间观众自动转为私信目标。

## 4. 交付

将时间线、关键问题、已发送文字与接口结果、待主持人处理事项保存到 Workspace 的 `xhs/live/<日期>-<room_id>/`。报告区分“实际观察”“建议”“已提交的动作”，不把提交当作送达。
