# 蒲公英合作 Workflow

适用：用户要找小红书达人、评估合作匹配度、拟定或发起蒲公英邀约。一个合作项目的研究与提案保存到 Workspace `xhs/cooperation/pgy/<项目名>/`。

## 1. 收敛合作条件

记录产品与品牌定位、目标客群、预算区间、内容形式、交付时间、地域限制、排除条件、允许的联系方式。缺失关键条件时先完成不依赖它的达人初筛，邀约前必须补齐。平台报价与商业数据会变，以本次接口返回和用户实际商务条款为准。

## 2. 验证平台身份并筛选

```bash
xhs-pugongying check
xhs-pugongying categories
xhs-pugongying search --choice '-1' --count 20
```

`check` 失败时停止，不把 PC 会话存在视为品牌账号已有蒲公英权限。按产品类目选筛选表达式，先取小批量，再按需要扩展；记录实际筛选条件、候选数和采集时间。候选账号去重后，用 `xhs-pugongying profile <user_id>` 获取总览、受众、趋势和作品表现。

## 3. 评估与拟邀

逐个核对品类契合、受众地区与年龄、作品调性、近期表现、历史合作与可能的商业冲突。给出入围/备选/排除及证据，不用单一粉丝量做结论。接口没有数据时写“未取得”，不要写 0。核对可见报价、预算与履约预期，形成可复核的候选表和合作建议。

将目标达人、产品名称、预计发布时间、邀约正文和联系方式写成 `proposal.json`，用 `xhs-pugongying invite --proposal <绝对路径>` 生成预览。向用户展示完整文案与接收方，确认后才执行同一命令加 `--send`。接口响应不明时先查蒲公英后台是否已有邀约，不重发。

## 4. 跟进

保存平台返回结果、邀约时间、待回复日期与下一步动作到项目记录。只有在实际查询到对方回应后才标记“已接受”或“已拒绝”；提交接口成功不等于合作成立。
