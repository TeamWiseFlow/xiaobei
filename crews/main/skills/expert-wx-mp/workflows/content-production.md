# 公众号内容生产 Workflow

从选题到发布的完整内容生产，覆盖两种产出形态：**公众号长文**（默认）与**小绿书图片贴**。用户说“帮我写一篇 XX”“出几篇稿子”“这篇的主题我们也写一篇”“用我们的风格改写这篇”“发个小绿书 / 图文贴”走这个。

## Step 0 - 入口判断

### 1. 识别产出形态

| 形态 | 判断 | 差异点 |
| --- | --- | --- |
| 公众号长文 | 默认 | 正文严格按 DNA template 执行；需要排版主题；走普通图文发布 |
| 小绿书图片贴 | 用户明确说小绿书 / 图文贴 / 图片轮播 | 图片为主体；封面与配图按用户要求生成或不生成；正文不套 DNA template；无排版主题；发布走 `wx-mp-publisher` 小绿书（图片消息）流程 |

### 2. 识别用户输入类型

| 输入 | 模式 |
| --- | --- |
| 只有粗略想法或方向 | 想法模式 |
| 参考文章（链接或文本） | 参考模式 |
| 已有草稿（本地 `.md` / `.txt`、PDF、Word，或用户直接输入的一大段思路） | 草稿模式 |

### 3. mp.weixin.qq.com 链接的意图判断

用户给公众号文章链接时，先判断意图：

- **风格吸收**：“把这篇的风格提取出来”“以后照着这个味道写”“融入到我们的风格里” -> 切换到 `style-dna.md` workflow，生成 report 并更新 DNA。
- **内容参考**：“参考这篇的主题写一篇”“写一篇同样内容的”“用我们的风格改写这篇内容” -> 继续本流程。
- 意图不明时先问用户：是吸收风格，还是参考主题内容。

### 4. 与改稿的边界

用户对一篇已完成的稿件（通常是我们此前产出的）做润色、换风格、换结构、换排版、压缩扩写，走 `editing.md`。本流程把用户输入当作素材，走完整生产链路产出新稿件。

## Step 1 - 生产契约锁定

### 1. 确定 DNA

生产必须绑定一个 DNA：

1. 用户明确指定 `dna-id` 时，只用该 DNA。
2. 用户没有指定时，用默认 `dna-0`。
3. 不得临场凭感觉拼一个风格，也不得改用 `default-business.md`。
4. 若目标 DNA 不存在，先按 `account-setup.md` / `style-dna.md` 建立或更新 DNA；完成前不进入写作。
5. 用户意图是把参考文章 / 参考账号的风格吸收进 DNA 时，先按 `style-dna.md` 处理，完成 DNA 更新后再回到本流程；仅参考主题内容时直接按本流程生产，不动 DNA。

写前必须读取两份文件：

```text
wx_mp/dna/{dna-id}/{dna-id}.dna.md
wx_mp/dna/{dna-id}/{dna-id}.template.md
```

DNA template 是选题、标题、段落结构、句式、语气和表达路线的直接执行依据；DNA 文档用于理解稳定性、例外和适用条件。

### 2. 核实业务事实与边界

读取 Workspace 根的 `business_knowledge.md`，按本次内容需要核实：

- 产品 / 服务概括和核心差异
- 目标读者与具体痛点
- 收费项目、转化目标或下一步动作
- 红线、合规限制和品牌语气

选题与内容方向按 DNA template 确定。涉及产品、服务、案例、承诺或 CTA 时，用业务知识核实事实与边界；关键信息缺失时先问用户，不虚构。

### 3. 采集生产要求

根据输入和 Memory 确定以下信息是否齐全，如有缺失一次性向用户问清：

| 项目 | 规则 |
| --- | --- |
| 产出形态 | 公众号长文或小绿书图片贴，未明确时默认长文 |
| 主题 / 方向 | 用户给了明确主题时不得另起炉灶，仅按 DNA template 细化选题和标题 |
| 素材 | 用户提供的文案、笔记、截图、链接、数据、案例必须优先使用 |
| 目标读者 | 未指定时按 DNA 受众关系推导；涉及业务事实时再核对 `business_knowledge.md` |
| 字数 | 长文未指定时按 DNA template，再无要求默认 1500-2500 字；小绿书正文按用户意图，不强行拉长 |
| 署名 | 用户指定或有要求 `author` 时逐字使用，如无默认使用 `xiaobei` |
| 原文链接 | 用户指定或有要求 `source_url` 时逐字保留；没有则不编造 |
| CTA | 用户指定 CTA 时优先执行；未指定时按 DNA template 判断是否需要及如何表达，涉及业务动作时核对业务知识；注意微信公众号不允许出现明显的二维码或者链接引流 |

优先级固定为：

```text
用户明确交付要求 + 业务事实 / 红线
> 用户提供的素材
> DNA template 的风格规则
> business_knowledge.md 中的相关事实
> Agent 的一般写作判断
```

DNA 约束的是选题角度、标题、结构、句式、语气和表达方式；不能覆盖用户指定署名、来源、CTA、事实和合规边界。

## Step 2 - 素材获取与整理

先建立文章目录 `wx_mp/outputs/<article-name>/`（article-name 用主题的短 slug；选题尚未确定时可先用暂代名，选题确定后随之定名），下设 `materials/` 子目录，获取到的素材统一放入 `materials/`。

1. 按类型获取输入：
   - `mp.weixin.qq.com` 链接 -> 调 `wx-mp-hunter fetch` 获取正文（需要封面时加 `--download-cover`）。
   - 其他链接 -> 用 web_fetch 或浏览器工具读取。
   - 本地 `.md` / `.txt` -> 直接读取。
   - PDF / Word -> 先提取正文文本（转成 `.md` / `.txt`）再进入流程。
   - 用户直接输入的大段文本 -> 直接作为草稿素材。
2. 建立素材清单：用户原话、事实、数据、案例、图片、链接、可用观点、待确认信息。
3. 区分三类输入：
   - **必用素材**：用户明确要求采用的事实、观点、案例和图文物料。
   - **参考素材**：提供方向或表达参考，不直接替代用户结论。
   - **对标素材**：只用于模式比较，不能覆盖用户素材和业务事实。
4. 素材不足时先补问；确实无法补充时，在稿中避免无证据断言。素材之间冲突时列出冲突并问用户；商业事实以 `business_knowledge.md` 和用户最新说明为准。
5. 用户意图是“保留内容、只换我们的风格”（同主题改写）时，整理**内容资产清单**而不是风格分析：主题、中心论点、事实、数据、时间、人物、案例、引用来源、需要保留的关键词、专有名词、免责声明。不能确认的信息标为「待核实」，禁止为了表达顺滑而补事实。

## Step 3 - 选题

### 选题调研（给出选题方向前执行）

先提炼 1-3 个核心关键词，用 `smart-search` 技能做一轮平台侧调研，再给选题方向：

1. **优先选社交 / 社区平台**搜索，按主题领域和目标读者选 1-2 个最贴合的平台：
   - 生活方式 / 真实体验 -> 小红书
   - 深度问答 / 观点讨论 -> 知乎
   - 热点 / 舆论 -> 微博、抖音
   - 视频题材 / 年轻受众 -> B站、抖音
2. 提炼该主题下用户的真实讨论、高频痛点、争议点和高热内容形态，作为选题依据。
3. 有价值的内容线索按 Step 2 素材清单归档为「参考素材」。

- ✅ 用 smart-search 走小红书 / 知乎 / 微博 / 抖音 / B站等平台，拿真实用户讨论做选题依据。
- ❌ 把通用搜索引擎（Bing / 百度 / 夸克等网页搜索）当选题调研首选——通用网页结果缺少真实用户声音和互动数据。仅在没有贴合的社交平台、或需核实客观事实数据时才兜底使用。

### 想法模式

结合用户想法、选题调研结论与 DNA template 的选题维度，给出 **3 个选题方向**，分别阐述理由，让用户挑一个。推荐理由必须同时覆盖：

1. 使用了哪些用户素材。
2. 对应 DNA 的哪些内容目标；如涉及业务目标，说明对应关系。
3. 符合 DNA template的哪些选题与受众特征。
4. 选题调研发现：相关主题在所选平台的讨论热度或用户痛点。

### 参考 / 草稿模式

从参考文章或草稿中提取选题方向，与 DNA template 的选题维度对比：选题已由参考文章或用户草稿确定时，可只做轻量调研（1 个平台、1 次查询）核实热度和痛点，不做全量调研：

- **相符** -> 直接采纳。
- **不相符** -> 明确指出差异，跟用户确认：综合调整以贴合 DNA，还是就用参考的选题。
- 用户明确换了主题（“仿写这篇，主题换成 XX”）-> 用用户给的新主题，参考文章只提供结构参考。

选题范围与角度以 DNA template 为准，优先使用相关的用户素材；业务知识仅核实选题涉及的事实、承诺与边界。

## 【确认】选题

第一个必停节点。确认的是方向，不是每个字。

- 小调直接改。
- 换主题、换读者、换转化目标 -> 重做本步。

## Step 4 - 标题

按 DNA template 列出的标题类型，每个类型各拟一个标题。

- 有参考文章或草稿时，必须参考其标题内容（如有），但不得照抄。
- 用户已指定标题或标题原则时，候选必须在该约束内生成，不得偷换方向。
- 标题硬限制：不超过 64 字节（约 21 个汉字）。

## 【确认】标题

第二个必停节点。务必与用户就标题确认。用户如果提出修改意见，按用户意见修改，直至与用户达成一致。

## Step 5 - 封面图 / 图片

### 公众号长文

1. 读取 DNA template 的封面图风格和封面 AIGC 提示词要素。
2. 结合最终标题、目标读者和本文核心收益，补齐本次封面的主体、场景、构图、色彩、光线、质感、文字视觉和负向约束。
3. 使用 `awk-img-gen` 生成封面图。
4. 用户已提供封面或封面素材时，可以基于用户已提供的封面或封面素材做编辑，补充必要要素。如果用户提供的不足以成为封面图，比如说尺寸偏小，元素不全等，则作为生成的参考。如果用户明确说：就按照他提供的，那就直接使用。
5. 生成的封面图发给用户确认，确认后保存到 `wx_mp/outputs/<article-name>/cover.jpg`。

### 小绿书

1. 小绿书不强制封面：按用户要求额外生成或不生成。
2. 用户一张图也未提供时，必须至少生成一张图，可按 DNA template 的封面要求生成。
3. 用户提供的图片全部进入 `image_list`（最多 20 张，首张为封面）；确认使用的图片统一复制到 `wx_mp/outputs/<article-name>/`。

## 【确认】封面

第三个必停节点。封面图确认，如果用户有意见，按照他的意见修改，直至确认。

## Step 6 - 初稿

初稿直接写入 `wx_mp/outputs/<article-name>/article.md`。

### 公众号长文

严格按 DNA template 写初稿：

1. 按 template 七部分（选题、标题、起、承、转、合、CTA）的段落任务、起步方式、句式节奏、语气和结构执行。
2. 用户必用素材优先进入正文，不得为了模板形状删除关键事实。
3. 商业承诺、服务范围、价格和案例必须与 `business_knowledge.md` 一致。
4. 用户指定 CTA 时逐字或按原意执行；未指定时按 DNA template 判断是否需要 CTA。需要时只选择一个下一步动作，不堆叠多个转化要求。
5. 同主题改写：只改写作风格和结构呈现，不改事实含义；数据、案例、引用和结论边界保持一致。

### 小绿书

正文不套 DNA template，按用户意图和选题确定的信息点书写；草拟后发用户确认。

### 文章配图准备规则

文章配图（含封面图），必须放置 `wx_mp/outputs/<article-name>/`（与`article.md`同目录），并按以下规则引用：

1. 正文图片写 `![说明](filename.jpg)`
2. `cover` 写 `cover: cover.jpg`
3. `image_list` 写 `- 1.jpg`
4. 只写纯文件名；不要写 `./filename.jpg`，也不要写目录路径或绝对路径
5. 所有本地图片文件名必须唯一；重名时先重命名再更新 Markdown
6. `http://` / `https://` 图片保留原 URL，不需要复制到本地

Agent 不需要手动上传图片；发布脚本会自动收集并上传上述本地图片。

## 【确认】初稿

第四个必停节点。按用户要求修改，直至与用户达成一致。

## Step 7 - Frontmatter

初稿定稿后，按 `wx-mp-publisher` 规范把 YAML frontmatter 直接写入 `article.md`。Frontmatter 在本 workflow 过程中加入，`wx-mp-publisher` 只做校验、不负责生成。

- 指定 `author`、`source_url` 时逐字或按原意执行；未指定时，author 使用 `xiaobei`, source_url不填。
- `need_open_comment` 和 `only_fans_can_comment` 按用户要求,如果没有要求的话，前者选True，后者选False。

公众号长文：

```yaml
---
title: 最终标题
cover: cover.jpg             # 可选，缺省自动取正文第一张图
author: 作者名称              # 可选，≤ 8 个汉字 / 24 bytes
source_url: https://...      # 可选，原文链接，仅用户指定时写入
need_open_comment: true      # 可选，是否开启评论
only_fans_can_comment: false # 可选，是否仅粉丝可评论
---
```

小绿书：

```yaml
---
title: 最终标题
image_list:
  - 1.jpg
  - 2.jpg
---
```

- 同时完成本地图片准备：封面图、正文配图、`image_list` 图片全部复制到 `article.md` 同目录，正文与 frontmatter 一律用纯文件名引用（不带目录前缀或绝对路径）；文件名必须互不重名，重名先重命名再更新引用。

## Step 8 - 存文件

定稿文章目录 `wx_mp/outputs/<article-name>/`：

- `article.md`（含 frontmatter）
- 封面图与配图（与 article.md 同目录）
- `materials/` 原始素材（Step 2 已放入）
- `dna-meta.json` 内容形如 `{"platform":"wx_mp","dna_id":"<dna-id>"}`，记录本篇所用 DNA（发布记录时 `published-track record` 自动读取建立关联，供后续 DNA 表现评估）

## Step 9 - 发布 + 记录

### 9-1. 排版选择（仅公众号长文，小绿书跳过）

排版独立于 DNA，不作为风格符合证据；排版在这一步选定：

1. 用户指定主题 -> 使用指定主题。
2. 用户未指定 -> Agent 根据文章内容自主选择：先看 `wx_mp/wenyan-theme/index.json` 有无可复用自定义主题，再按 `wx-mp-publisher` 的决策树从内置主题中挑选，不丢给 relay 默认。
3. 用户要求对标排版（“照着这篇的排版来”）-> 调 `generate-wenyan-theme` 提取参考文章排版风格生成主题，登记到 `wx_mp/wenyan-theme/index.json`。
4. 自定义主题把登记的 `theme-id` 直接传给 `wx-mp-publisher`（脚本经 `wx_mp/wenyan-theme/index.json` 解析出 CSS 并随请求上传 relay）；直接传 `.css` 文件路径也可以。

### 9-2. 发布

调 `wx-mp-publisher <article.md> [theme] [--account ALIAS]` 推草稿箱：

- 小绿书：frontmatter 有 `image_list` 时自动走图片消息接口，忽略主题参数。
- 脚本自带发布前校验（图片纯文件名引用、`author` 长度），校验失败直接退出。
- 必须等待脚本完整返回后再判定结果，禁止提前自行判断发布成功。

### 9-3. 公众号特例：media_id 占位与 URL 升级

`wx-mp-publisher` 只能把文章发布到微信公众号后台草稿箱，正式发布必须由用户手动至微信公众号后台操作：

1. 调用成功后 relay 返回草稿的 `media_id`；暂时将 `media_id` 作为文章 url 占位，先调 `published-track record` 完成入库：`--platform wx_mp`、`--source-folder wx_mp/outputs/<article-name>/`、`--account <发布所用账号 alias>`（`dna_id` 自动从 `dna-meta.json` 读取）。
2. 告诉用户去公众号后台草稿箱正式发布。
3. 后续用户完成正式发布并提供了正式 URL 时，用相同 `--source-folder`、`--publish-date` 重跑 `published-track record` 并传入正式 `--publish-url`——upsert 语义会升级对应记录的 URL，不重复插行。

小绿书记录同理：入库时同样用 `media_id` 占位，用户提供正式链接后升级。
