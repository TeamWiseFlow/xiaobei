# 互动与联络 Workflow

适用：已有明确目标的评论/回复、点赞收藏关注、私信、邮件和后续联络。先读[互动能力表](../references/interaction-capabilities.md)，再读所选工具的 SKILL.md；只执行当前 crew 已配置且工具已实现的动作。

需要先找客户时使用 [Lead Hunting](lead-hunting.md)；商业情报与竞对研究使用 `expert-osbi`；内容创作、发布和本人作品取数交对应平台专家包。直播发言与点赞使用 [Live Interaction](live-interaction.md)。

## 1. 确定目标、任务与授权

确认平台、使用的账号、真实目标、互动目的、发送内容或允许的答复范围，以及本次动作数量。已有授权覆盖的目标与内容直接沿用；没有写操作授权时只读取和准备草稿。换收件人、换账号、增加媒体或超出原答复范围时重新核对授权。

保留完整作品链接、用户 ID、评论 ID 或会话 ID。抖音私信收件人使用真实数字 UID，不能把 sec_uid、昵称或主页短链当作 UID；其他平台同样按工具说明使用正确的 ID。首次联络或接收一条消息，不等于允许持续群发、自动回复或转到其他渠道。

## 2. 取得真实语境并查重

- 公开作品、评论、账号和通知分别使用 `douyin-hunter` / `xhs-hunter` / `tiktok-hunter` / `kuaishou-hunter` / `x-hunter` / `weibo-hunter` / `youtube-hunter` / `wx-mp-hunter`，以各工具实际范围为准；保留来源与完整标识，小红书访问令牌按 `xhs-hunter` 说明保留。
- 私信语境由对应 IM 工具读取。抖音 `douyin-im listen` 只提供监听窗口内的实时事件，`info` 只核对已保存会话；小红书 `xhs-im` 可读会话、历史、未读与实时消息；TikTok `tiktok-im` 可读会话、历史与实时消息。X 的 `twitter-im history` 是加密占位结果，不据此编造对方说过的话。
- 优先复用用户提供的上下文、Lead Hunting 或 `expert-osbi` 已留存的本轮资料。语境不足时明确缺项，不用猜测的历史、身份或企业关系补齐。
- 用 `bd-record` 按其支持的创作者或帖子标识查重，同时核对 Workspace `bd/` 的联络日志及工具回执。已有成功提交或未知结果时先处理原任务，不能换请求编号、作品目录或渠道重复触达。

合作洽谈确需核验企业主体时，按[本包安装与授权规则](../SKILL.md#安装与授权规则)使用 `tyc`，以真实企业全称或统一社会信用代码查询，复用本轮已有资料。普通评论/私信不强制企业查询；无数据、额度不足或无权限标为未完成，不当作核验通过。企业登记不能单独证明某人的任职或联络身份。

## 3. 按渠道准备动作

### 作品、评论与账号互动

抖音用 `douyin-interact`，TikTok 用 `tiktok-interact`，X 用 `twitter-interact`，YouTube 用 `youtube-interact`。评论、回复、点赞、收藏、转发或关注只选择能力表中该平台已实现的动作；回复必须引用原平台真实评论或帖子标识。小红书笔记、快手及微博尚无已接入的普通互动写工具，不能借用直播评论或浏览器代发。

先准备与原讨论相关的内容，不冒充认识对方。X 回复遵守 `twitter-interact` 的权重与长推权限规则；YouTube 评论需账号有频道，不因权限不足自动创建频道。

### 抖音私信

读取 [douyin-im](../tools/douyin-im/SKILL.md)，按以下任务选择已有脚本，不手工拼接会话文件、身份票据或上传中间状态：

- **主动联络指定用户**：使用 `send-to`，脚本按当前账号复用并刷新会话，必要时创建。每次授权任务使用稳定的 `--request-id`；目标和内容未变的续接沿用原编号，不为绕过未知结果换编号。
- **发送媒体或卡片**：`send-to/send` 支持文本、本地图片、视频、附件和视频分享卡片；其他分享卡片、贴纸或已有语音内容按工具要求提供真实内容对象。本地音频直接上传为语音尚未实现。预览时核对真实文件、媒体类型与收件人，未确认不上传。
- **回复实时入站消息**：`listen` 使用有限时长、事件上限和受控输出文件；`reply` 根据事件文件与真实服务端消息 ID 选择入站消息，核对当前账号、发送者和会话，多条匹配时精确指定会话。工具向同一会话发普通消息，尚不支持引用气泡；没有单独授权不自动回复所有事件。
- **已有会话与原请求续接**：`info/send` 仅处理工具已保存的会话，旧票据由脚本刷新；`status --request-id` 查询本地回执。完整平台会话列表、离线历史补拉、未读数、主动标已读、撤回与删除未实现，不用 `info/status` 冒充这些能力。

按任务与原始内容选择受支持的消息类型，参数与限制以工具说明为准；`--request-id` 仅用于声明支持该参数的工具。

### 其他平台私信与邮件

- **小红书**：使用 `xhs-im`。单聊可发文本、标已读、撤回本人消息或删除本账号会话；群聊仅列表和历史。游标、未读统计和消息标识由工具维护，不手填全局计数。用户已授权的自动回复流程仍须遵守其本地防重与平台提示判断规则。
- **TikTok**：使用 `tiktok-im`，只向真实已有会话发送文本，可做有界监听；新建会话、媒体发送、标已读、撤回与删除未实现。写操作需要同次登录的 ticket-guard 材料。
- **X**：`twitter-im` 只做有限会话与加密历史查询，不支持发送、解密正文或实时监听。快手、微博和 YouTube 无已接入私信能力，明确报告缺口，不改走浏览器或其他账号补发。
- **邮件**：按公共 `email-ops` 的技能说明执行。收件人、主题、正文和附件有真实依据，沿用已有发送授权；不要把社交平台私信授权自动扩成邮件授权。

## 4. 预览并执行已授权动作

各平台登录按所选工具说明执行：抖音共用 `douyin-login` API 会话，小红书复用 `xhs-hunter` PC 会话，TikTok、X、YouTube 分别由 `tiktok-hunter`、`x-hunter`、`youtube-hunter` 管理。只准备当前动作需要的会话与安全材料，不混用 Creator Cookie，不从其他账号拼凭据。

默认预览时核对账号、真实目标、最终文字、媒体与动作范围。已有授权且预览一致时按工具加 `--confirm` 执行，不再重复索取同一许可。邮件按 `email-ops` 的实际发送方式处理，不给它套用平台参数。

Relay 只算签名，平台请求仍由客户端发出。缺少部署入口、OFB_KEY、签名材料、配额或权限时报告对应缺口；不切本地签名、不把 Relay 错误当作登出。验证码、限频、账号限制或连接异常按工具返回停止，不自动解验证码、换账号或换渠道重试。

## 5. 按证据确认结果

- **预览**没有提交；工具返回成功也须区分受理、公开可见、送达、已读及对方回应，不能互相替代。
- **抖音作品互动**的 `accepted=true` 仅表示平台接受操作。`account_state_verified=false`、`visibility_verified=false` 表示最终账号状态或评论可见性未核验；不能把原始 `is_digg=0`、`collects_flag=false`、评论状态数字或作品总数变化解释为失败后再操作。
- **抖音私信**以请求回执的 `status/accepted/evidence` 判断。`platform-ack` 不等于业务消息已送达，`business-response` 也不等于对方已读；`user-confirmed-app` 是用户核实结案，不能说成工具解析出了平台消息 ID。`status` 命令退出码0只表示本地查询完成。
- **原任务续接**：抖音 `preparing/prepared` 可按原目标、内容和编号处理错误后续接；`submitting/unknown` 停止重发，明确拒绝的 `rejected` 本任务也不自动重试。其他平台同样先核对原提交证据，小红书 WebSocket 的 submitted/mid 不能直接说成送达。

结果未知时保留回执与脱敏诊断，按该平台已实现的读取能力或用户从 App 核实的结果处理。没有历史/送达查询接口时如实说明，不虚构核验；不为取得回执重复发送，不删除未知收据再发送。

## 6. 留存与交付

真实目标、账号、动作、最终内容、时间、来源、请求编号、回执路径与结果存入 Workspace `bd/` 的本次联络日志，凭据和原始敏感回包不贴入对话。`bd-record` 只按现有创作者/帖子类型记录；预览、失败或未知不能标为已互动，私信或邮件没有真实来源帖子时不编造帖子 URL。原始私信事件与媒体按工具要求存受控目录。

向用户说明已执行什么、证据确认到哪一步、对方实际回应及待跟进事项。新增持续监听、自动回复或周期跟进须有明确范围，不能因本次联络顺手创建定时任务。
