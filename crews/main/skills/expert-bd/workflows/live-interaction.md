# Live Interaction（直播间互动）

适用：用户要求在指定抖音/小红书公开直播间参与讨论、提问、答疑或拓展合作。目标可以是他人的直播间，也可以是自己的直播间；主要使用观众侧互动能力。竞争对手调研走 [Live Research](live-research.md)。

## 1. 明确目标与授权

确定目标房间、主播、使用的登录账号、互动目的、允许的文案或答复范围、参与时长与次数。遵守已有授权，不重复索取同一动作的确认；只有目标或内容超出授权范围时才补充确认。授权未覆盖发送时只观察并准备草稿。

不将进入直播间或收到观众事件视为私信授权；后续合作私信另按 [Interaction](interaction.md) 执行。自己的房间可用于文字答疑与问题整理，主播后台禁言、踢人、开关播和商品管理仍由平台后台处理。

## 2. 观察房间语境

读取 `references/interaction-capabilities.md` 与对应 live 工具说明，按其要求检查登录态、核对房间状态与真实目标信息。内容与账号资料用一级 hunter；互动使用本包 live 工具，不混用创作者 profile 登录态。

在约定窗口内观察实际评论、话题与房间返回的信息，选择与讨论相关的提问或回复；无依据的价格、库存、优惠和产品事实先核实。直播有访问或发言限制时停止对应动作并报告，不自动换账号或不断重试。

## 3. 执行已授权互动

- **抖音**：使用 `douyin-live chat` 发弹幕；明确授权点赞时使用 `douyin-live like`。目标参数、文本长度与点赞次数遵循工具说明，先预览，实际执行加 `--confirm`。
- **小红书**：使用 `xhs-live send` 发直播文字评论，带实际目标 room_id 和主播 host_id；先预览，实际执行加 `--confirm`。直播点赞尚未实现，不调用笔记互动或赠礼接口代替。
- 每个动作依据本次讨论与授权执行。监听本身不触发自动回复、刷屏或自动私信；仅在用户明确要求自有房间答疑时，按授权的事实与答复范围协助回复。
- 不执行赠礼、充值或其他支付操作。提交成功只记“已提交”；实际出现或送达需另有房间证据。超时、异常或结果不明时先核对，不能自动重发或换通道补发。

## 4. 结果与跟进

将目标房间与主播、登录账号标识、动作时间、确切文案、接口结果及实际回应保存到 Workspace `bd/live/<platform>/<日期时间>-<room_id>/`，下一轮互动前核对历史，避免重复触达。

直播动作保留在该目录的互动日志，不把直播间强行写成 `bd-record` 的帖子互动；其现有 schema 没有直播事件/点赞记录类型。后续创作者线索或评论/私信触达按 `bd-record` 已支持的类型记录。

向用户交付实际参与情况、对方回应、合作机会与待跟进事项，区分已提交、已核实和未知结果。不要将预览、无事件输出或尚未真实账号验收的接口当作成功互动。
