# Investor Hunting（投资人发掘）

通过搜索渠道主动发掘潜在投资人/投资机构，按匹配度筛选，去重记录到 `ir-record`，可选发起触达。

**依赖**：`smart-search`（构造搜索 URL）、`browser-guide`（浏览器操作）、Investor Outreach Workflow（触达话术）、`email-ops`（邮件）、`ir-record`（去重记录）。

**可选工具**：天眼查 CLI `tyc`（投资机构企业背景核验，默认未安装；先遵循本包 SKILL.md 的安装与授权规则）。

---

## 前置条件

执行前需确认以下信息（默认一次性任务，逐项向用户确认；若已启用定时模式则来自 HEARTBEAT.md 配置，见包内 `scheduling.md`）：
- 目标投资人类别（angel/vc/pe/cvc）和关注领域
- 搜索渠道列表及对应搜索关键词
- 匹配度判定标准（投资阶段、领域、管理规模、已投案例等）
- 每次最大探索量
- 反馈形式（列表报告 / Email 联系 / 社交平台触达）

---

## 搜索渠道

| 渠道 | 方式 | 说明 |
|------|------|------|
| 投资数据库 | `smart-search` + browser | IT桔子、企查查等——搜索投资事件、机构列表 |
| 天眼查企业核验 | 官方 CLI `tyc` | 按已确认的机构法律主体查询工商、股权及风险，补充机构背景；品牌名不等于基金管理公司或签约主体 |
| 融资新闻 | `smart-search` | 搜索"XX轮融资"、"XX领投"——从新闻中提取参投方 |
| 竞品融资记录 | `smart-search` | 搜索竞品融资新闻，提取其投资人作为潜在目标 |
| 社交平台 | `smart-search` + browser | 微博/小红书/即刻——搜索投资人内容、创投圈讨论 |
| LinkedIn | `browser-guide` | 搜索投资人 profile（需登录） |

## 执行流程

### Step 1: 准备工作

1. 确保浏览器可用（遵循 `browser-guide`）
2. 初始化 ir-record 数据库（幂等）：`ir-record init-db`

### Step 2: 逐渠道搜索

对配置的每个网页搜索渠道，按顺序执行；天眼查企业核验在 Step 3 按需执行，不构造网页搜索 URL：

1. 使用 `smart-search` 构造该渠道的搜索 URL
2. 导航到搜索结果页，等待加载
3. 收集搜索结果中的投资人/机构信息（最多取配置的最大探索量）
   - 提取：姓名、机构、职位、关注领域、来源 URL

### Step 3: 逐投资人判定

对每个搜索到的投资人/机构，按顺序执行：

1. **去重检查**：
   ```bash
   ir-record check-investor --name <姓名> --firm <机构名>
   ```
   如果 `{"exists": true}`，则跳过，继续下一个

2. **获取更多信息**（如搜索结果信息不足）：
   - 导航到投资人/机构详情页（投资数据库 profile、LinkedIn 等）
   - 读取投资偏好、已投项目、管理规模等信息
   - 需要机构主体或风险核验时，按本包 [SKILL.md 的安装与授权规则](../SKILL.md#安装与授权规则) 使用 `tyc`：已安装直接使用；仅未安装时先展示免费额度与计费规则，再征求安装同意，得到同意后才安装。
   - 下列为按需选用的独立查询示例，将示例企业替换为已确认的机构法律主体全称或统一社会信用代码，不直接套用基金品牌名：
     ```bash
     # 工商登记
     tyc company registration-info "乐视网信息技术（北京）股份有限公司" --head 80

     # 股东结构（需要相应数据权益）
     tyc company shareholder-info "乐视网信息技术（北京）股份有限公司" --head 80

     # 基础风险总览
     tyc risk overview "乐视网信息技术（北京）股份有限公司" --head 80
     ```
   - 查询资料存到 Workspace `ir/` 本轮资料目录，记录企业全称、信用代码、与机构品牌的对应依据、来源（天眼查及所用命令）、查询时间与未核实项，并在投资人 notes 中保留摘要及资料路径。`--head` 只限制展示行数，完整结果按 SKILL.md 在同一次查询中保存；企业信息不能直接证明某人的任职、基金投资偏好或可投资金额。

3. **匹配度判定**（按预设判定标准）：
   - 投资阶段是否匹配（种子/天使/A轮/...）
   - 关注领域是否与公司业务相关
   - 管理规模是否在目标范围
   - 已投案例是否有同类/相邻赛道
   - 判定为潜在投资人需给出明确理由和匹配度评分（high/medium/low）

4. **记录到数据库**（不管是否符合标准）：
   ```bash
   ir-record record-investor \
     --name <姓名> --type <angel|vc|pe|cvc|fo|other> --firm <机构名> \
     --title <职位> --email <邮箱> --source <来源> \
     --focus-areas <关注领域> --match-score <high|medium|low> \
     --status new --notes <判定理由>
   ```

5. **操作间隔**：每个投资人之间保持 30-60 秒间隔，避免平台风控

### Step 4: 汇总报告

1. 统计本批次结果：探索总数、符合数、跳过数（已记录）

2. 列出所有符合标准的潜在投资人：
   - 姓名、机构、职位、匹配度、关注领域、判定理由、来源

3. 按配置的反馈形式执行：
   - **列表报告**：仅汇总报告，不触达
   - **Email 联系**：对 high 匹配度的投资人，按 Investor Outreach Workflow 生成话术，经用户确认后用 `email-ops` 发送
   - **社交平台触达**：对 high 匹配度的投资人，通过社交平台私信触达（需用户确认）

4. 使用 message 工具将汇总报告发送给用户

## 错误处理

| 情况 | 处理 |
|------|------|
| 渠道搜索结果为空 | 记录渠道名称，跳过，继续下一个 |
| 投资人详情页无法访问 | 记录"无法访问"后跳过，不阻塞流程 |
| 天眼查未安装且未获安装同意、额度不足、无权限或无数据 | 分别标注企业背景未核实及原因，继续可完成的搜索与筛选，不写成“核验通过”或“无风险” |
| 浏览器异常 | 等待 30 秒后继续；若仍不行，等 30 秒再试；关闭重开后仍报错则停止并反馈用户 |
| 平台风控/验证码 | 停止当前渠道操作，记录并继续下一个 |
| 持续错误 | spawn IT Engineer 协助排查，当前任务标记为部分完成 |
