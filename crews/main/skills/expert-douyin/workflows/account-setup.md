# 起号、定位梳理与老号接手 Workflow

`douyin-hunter comments` 返回平台限流或接口错误时停止本轮评论采样，标注评论数据不可得或样本不完整；不把接口错误当作零评论或登录失效。

新号起号、账号定位梳理、内容支柱搭建、默认 `dna-0` 初始化、老号接手与诊断走这个 Workflow。独立账号对标走 `account-benchmark.md`。

起号拆成六件事：定位清楚、观看理由成立、标签稳定、内容有用、互动真实、复盘持续；平台功能入口、算法权重、处罚规则按待确认信息处理。产出要能直接执行：表格、清单、话术简报、选题池或复盘动作，少写空泛建议，多给"下一条视频该怎么做"。

## 入口判断

用户说以下话时走：

| 意图 | 典型说法 | 处理 |
| --- | --- | --- |
| 新号起号 | "我想做个抖音号，从零开始" | 业务信息检查 -> 定位梳理 -> 初始 `dna-0` |
| 定位梳理 | "梳理一下内容方向""搭建内容支柱" | 定位梳理 -> 必要时更新 `dna-0` |
| 老号接手 | "这个号以后你来接手""账号还行，先按原风格做" | 老号样本采集 -> 建立或更新 `dna-0` |
| 老号诊断 | "帮我看看这个号还有没有救""给我们号把个脉" | 老号样本采集 + 诊断速查 -> 判断延续或重建 |
| 默认 DNA 初始化 | "初始化默认 DNA" | 按新号 / 老号路径建立 `dna-0` |

## 从零开始打造新号

### 初始化原则

1. 默认 DNA 固定为 `dna-0`。
2. 除 `account-benchmark.md` 分流的对标样本外，用户不指定 DNA 时，参考视频和后续新增样本默认累积到 `dna-0`。
3. `dna-0` 可以由参考账号、参考视频、用户想法和 `business_knowledge.md` 共同形成，不绑定单一账号名。
4. 若 `douyin/dna/dna-0/dna-0.dna.md` 已存在，不覆盖重建；新资料按 `style-dna.md` 的更新流程进入。
5. 独立对标样本不直接写入 `dna-0`，必须走 `account-benchmark.md` 并进入独立 DNA；用户明确采纳的局部规则可通过局部 DNA 融合更新 `dna-0`。

### Step 1 - 业务信息检查

先读取 Workspace 根目录的 `business_knowledge.md`，检查三项关键信息：

| 关键信息 | 最低要求 |
| --- | --- |
| 产品 / 服务概括 | 能说明卖什么、解决什么问题、核心差异 |
| 收费项目 | 能说明主要收费方式、产品或价格区间 |
| 目标受众 | 能说明具体人群、痛点、使用场景 |

任一项为空、仅有占位符或互相矛盾时，先与用户补齐。不要凭空编造。

用户思路不清晰、多个定位方向难以取舍或商业假设冲突时，调用顶层 `council` 技能辅助梳理；`council` 不收纳进抖音专家包。

更新 `business_knowledge.md` 前必须征得用户同意，并遵守 Workspace 根 `AGENTS.md` 的治理规则。

### Step 2 - 定位梳理

新号起号、老号重建和用户要求"梳理定位 / 内容支柱"时都必须执行。已有清晰定位且用户只要求接手制作时，可以基于现有账号样本校验定位，不重新发起完整讨论。

#### 输入

1. `business_knowledge.md` 中的产品、服务、收费、受众和红线。
2. 用户目标：IP 信任、获客、销售、社群、直播引流或品牌曝光。
3. 已有账号样本和表现线索（如有）。
4. 用户提供的对标方向（如有）。

#### 输出（起号计划字段）

1. **定位句**：我帮助[目标观众]，用[方法/内容承诺]解决[具体痛点]，让他们获得[理想结果]。
2. **观看理由**：陌生人为什么要看完这条而不是划走；看完能记住账号的哪个身份、冲突、热情或承诺。每条视频都要能回答这两个问题，回答不了的选题不做。
3. **内容支柱**：3-5 个，分别承接搜索、信任、故事、证明、转化或留存。
4. **关键词地图**（标签反推 + 搜索预埋）：
   - 选 5-10 个对标账号，优先低粉高互动、近期更新、评论真实、内容形式可学习的账号；请用户提供账号名或视频链接，Agent 用 `douyin-hunter user-posts` 取代表作、`viral-chaser` 逐个拆解，并用 `douyin-hunter comments` 抓取对标视频评论，记录主标签、细分人群、核心场景、常见痛点、标题高频词、评论高频问题。
   - 汇总成 `1 个主标签 + 2-4 个场景词 + 3-5 个人群痛点词`，并按关键词层级展开：核心词（赛道本体）、长尾痛点词（用户真实搜索句）、场景词（时间/人群/预算/身份）、转化词（清单/步骤/避坑/对比/测评/教程）。
   - 这些词写进昵称、简介、置顶视频、前 10 条标题、口播首句、合集名称和结尾关注理由。
5. **主页文案**：昵称、简介、置顶视频规划。
6. **选题库雏形**：每个支柱至少 5 个候选选题，前 30 条选题按 30 天节奏排布。
7. **约束与风险**：合规边界、宣传限制、版权、品牌语气、产能。

用户思路不清、多个方向冲突或商业假设不一致时，先用少量问题澄清；仍难判断时调用顶层 `council` 技能辅助决策。

普通内容改造参考（把平铺内容变成有观看理由的版本）：

| 平铺内容 | 可看版本 |
| --- | --- |
| 展示产品很好 | 发起一个有趣的复刻、挑战、测评或对比系列 |
| 讲自己很专业 | 公开解决一个真实难题，并展示判断过程 |
| 直接教知识点 | 带着具体场景、限制条件或失败案例去解决 |
| 展示日常工作 | 把工作过程包装成任务、闯关、实验或复盘 |

### Step 3 - 新号初始 DNA 路径判断

先区分两种"参考"：

- 用户明确要把参考账号或视频作为默认 DNA 的初始来源 -> 走下方路径 A / B / C，产物进入 `dna-0`。
- 用户只是要分析参考账号、比较风格差异或寻找可借鉴模式 -> 走 `account-benchmark.md`，对标样本进入独立 DNA，不直接写入 `dna-0`。
- 意图不明确时，先向用户确认"是纳入默认 DNA，还是只做对标比较"。

#### 路径 A：用户提供了参考账号或参考视频

1. 按 `style-dna.md` 获取样本：
   - 视频链接：self-spawn subagent 走 `viral-chaser` 拆解
   - 本地文字稿 / 脚本：直接整理为转录 `.md` 输入 profiler
2. 目标 DNA 固定为 `dna-0`。
3. 每条生成 report。
4. 运行 `douyin-style-profiler build --dna-id dna-0`，生成 DNA 文档与 template。
5. 把定位、选题、标题包装、账号简介、内容形式与比例、发布习惯、高数据创意、口播 DNA 与制作管线发送用户确认。
6. 用户调整意见按 `style-dna.md` 的"用户输入转译"更新到 `dna-0`。

用户没有明确权重时，所有 report 默认权重为 1。

#### 路径 B：用户暂无参考，但业务信息完整

Agent 基于 `business_knowledge.md` 和关键词地图提炼搜索关键词，建议用户到抖音搜索头部或表现较好的账号 / 视频（也可用 `smart-search` 辅助发现）。

给用户的搜索建议必须说明：

1. 优先找观众相近、承诺清晰、近期仍活跃的账号；优先低粉高播账号（粉丝少但播放高，说明内容形式可学习）。
2. 优先选择点赞、评论、分享信号强的视频；播放量只作参考之一。
3. 对标账号初始参考建议批量收集 10 条作品（视频进 `dna-0`，图文进 `dna-0-note`）；用户明确提供单篇或少量样本时仍可建立 DNA，但必须标注覆盖不足，不得称为稳定结论。批量账号样本才填账号运营子模块（简介写法、内容形式比例、发布习惯）。
4. 抖音没有账号作品列表抓取工具；用户找到账号或视频链接后，Agent 再用 `viral-chaser` 拆解和提炼。

用户补回账号名或视频链接后，回到路径 A。

#### 路径 C：用户拒绝外部参考或已有明确想法

1. 结合 `business_knowledge.md`、用户定位、目标观众、变现方式和用户思路，提炼 `dna-0`。
2. Agent 直接按维度框架编写（视频用 `video-dna-framework.md`，图文用 `note-dna-framework.md`）：

```text
douyin/dna/dna-0/dna-0.dna.md
douyin/dna/dna-0/dna-0.template.md
```

3. DNA 文档必须标明来源是"业务信息 + 用户指定方向"，没有视频样本统计。
4. 能确定的规则写为执行要求；未确定维度写"待校准"，不得虚构单条证据。
5. Template 仍必须给出可执行语义段：视频 = Brief 正文 + 口播文案模板；图文 = 图文写作模板。不能只有抽象定位词。
6. 将 DNA 摘要和待校准点发给用户确认，再按用户意见转译修订。

后续获得真实视频样本时，按 `style-dna.md` 生成 report 并更新 `dna-0`。

### Step 4 - 默认 DNA 落盘

完成路径 A / B / C 后，确认以下文件存在且互相一致：

```text
douyin/dna/dna-0/reports/
douyin/dna/dna-0/covers/
douyin/dna/dna-0/dna-0.dna.md
douyin/dna/dna-0/dna-0.template.md
```

检查要求：

- DNA 文档说明样本来源、覆盖数量、权重、例外和待校准点。
- Template 能由 DNA 文档推导，直接指导定位、选题、标题包装、内容形式、发布节奏、高数据创意、互动与制作交接。
- 用户输入已转译为维度级规则，不是原话堆积。
- 对标样本 report 不混入 `dna-0`；用户采纳后，只有转译后的规则通过局部 DNA 融合进入 `dna-0`。

### Step 5 - 定位验证（九条视频实验，可选输出）

适合新号、低播放号、定位需要验证的账号。目标不是保证涨粉，而是在一周左右拿到第一批可比较信号。产出实验设计表交用户确认：

| 序号 | 选题角度 | 观看理由 | 3秒钩子 | 人格/短板/热情 | 放大层 | 搜索词 | 评论问题 | 验证假设 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 痛点教程 | | | | | | | |
| 2 | 失败复盘 | | | | | | | |
| 3 | 公开挑战 | | | | | | | |
| 4 | 案例拆解 | | | | | | | |
| 5 | 反常识观点 | | | | | | | |
| 6 | 清单避坑 | | | | | | | |
| 7 | 评论答疑 | | | | | | | |
| 8 | 场景实验 | | | | | | | |
| 9 | 系列预告/总结 | | | | | | | |

前提：9 条视频必须属于同一个定位和人群；每条只改变 1-2 个关键变量（钩子、场景、选题角度或人格表达）；每条都要有明确观看理由，不为凑数发布。

复盘方式（实验结束后按 `review.md` 的复盘字段执行）：先排除违规、搬运、画质严重问题和标题误导；计算账号内部中位数，找明显高于中位数的视频；用 `douyin-hunter comments` 抓取高表现视频的评论（自己账号的视频同样可抓），标注用户喜欢的具体原因；选一个最可能有效的变量做下一轮 3 条验证，不要一次改完所有东西。

## 老号接手

### Step 1 - 获取老号样本

1. 抖音没有账号作品列表抓取工具；请用户提供老号最近的代表性视频链接（原则上至少 10 条，账号作品不足 10 条时提供全部并说明）。
2. 拿到链接后逐条 self-spawn subagent 走 `viral-chaser` 拆解，剔除重复、删除和无效样本；保留标题、描述、发布时间、账号简介、内容形式、时长、互动线索和关键帧。
3. 用户也可补充后台截图（播放、完播、粉丝画像），作为诊断线索，不编造。

### Step 2A - 账号基本可用，用户让 Agent 接手

用户对账号目前的情况基本满意，目的是让 Agent 接手，延续目前账号的风格。

1. 将老号视频生成属于 `dna-0` 的 DNA report。
2. 若 `dna-0` 不存在：运行 `douyin-style-profiler build --dna-id dna-0`，建立默认 DNA 文档与 template。
3. 若 `dna-0` 已存在：新增 report 后按 `style-dna.md` 更新 `dna-0`，不覆盖重建。
4. 将 DNA 摘要、可复用规则和待校准点发给用户确认。
5. 用户意见按"用户输入转译"更新 `dna-0`，后续内容生产默认使用 `dna-0`。

### Step 2B - 用户认为账号不太可用，需要推倒重来

1. 基于 Step 1 拿到的样本提炼定位、账号简介、选题组合、标题包装、内容形式、发布节奏、核心卖点与 CTA 等基础信息，将这些信息与用户确认。
2. 结合上述信息，走「从零开始打造新号」流程。
3. 如果 `business_knowledge.md` 不全，可以先从 Step 1 的样本中提取，不足的信息与用户讨论。

### 老号诊断速查

有样本时先自行分析（内容支柱、垂直度、钩子、标题、封面、互动设计、发布频率），再向用户补问缺失信息。按失败环节倒推：

| 信号 | 可能问题 | 优先动作 |
| --- | --- | --- |
| 曝光低 | 账号标签弱、内容垂直度不足、违规风险、样本太少 | 收窄主题，查风险词，连续发布同一内容支柱 |
| 点击低 | 封面/标题没说清人群和收益 | 重写标题，首帧突出痛点和结果 |
| 完播低 | 钩子虚、节奏慢、信息密度不均 | 前 3 秒改冲突，中段改步骤，删空话 |
| 评论少 | 缺少可回答问题，内容没有争议点或共鸣点 | 结尾问具体问题，承接真实评论 |
| 关注少 | 账号承诺不清，单条有用但系列价值弱 | 加强主页、置顶、合集和结尾关注理由 |
| 搜索少 | 标题和正文缺少长尾词 | 补关键词地图，做搜索型选题 |
| 记不住人 | 身份信号弱、人格张力弱、内容太像资料搬运 | 加入真实场景、短板、判断标准或系列任务 |
| 评论质量低 | 引导过浅或吸引错人 | 改成场景问题，减少泛福利引导 |

阈值只作为经验提示，不能机械判断。样本太小时，先收集 10-20 条同类内容再做大调整。诊断结论指向系统性风格问题时，引导走 `review.md` 做 DNA 评估。
